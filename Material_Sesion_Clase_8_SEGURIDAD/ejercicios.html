Ejercicio 1 — Verificar estado actual

Antes de agregar seguridad, verifica que tu app funciona.

  1. Abre tu terminal en la carpeta del proyecto.
  2. Ejecuta: ./mvnw spring-boot:run
  3. Abre http://localhost:8080
  4. Verifica: listar, crear y ver registros funciona.
  5. Abre tu URL de Render en el navegador — ¿sigue activa?
Si localhost no funciona, NO sigas
Resuelve errores locales primero. Agregar seguridad sobre código roto duplica los problemas.

  1. Guarda el archivo y reinicia la app.
  2. Abre http://localhost:8080 — ¿qué ves?
  3. Busca en la consola una línea que dice Using generated security password:
  4. Prueba iniciar sesión con usuario user y esa contraseña.

Ejercicio 4 — Crear la vista de login

Crea templates/login.html con el formulario del material interactivo.

  1. Incluir campos username y password.
  2. Usar th:action="@{/login}" y method="post".
  3. Agregar mensajes: error si param.error, éxito si param.logout.
  4. Agregar @GetMapping("/login") al controlador.
¿Por qué th:action? Thymeleaf agrega automáticamente el token CSRF al formulario. Si usas action normal en HTML, el POST dará error 403.

Ejercicio 5 — Agregar botón de logout

En tu vista de lista (o en el navbar), agrega:

<form th:action="@{/logout}" method="post">
  <button class="btn btn-outline-danger btn-sm">
    Cerrar sesión
  </button>
</form>
  1. Agrega el formulario a tu vista.
  2. Reinicia y prueba: login → ver recursos → logout → ¿redirige al login?

¿A dónde redirigió el logout?

Ejercicio 6 — Getter calculado con @Transient

Agrega un campo calculado a tu entidad. Elige uno:

  • Total: getTotal() = precio × cantidad
  • Edad: getEdad() a partir de fechaNacimiento
  • Estado: getEstado() según cantidad y activo
@Transient
public double getTotal() {
    return precioUnitario * cantidad;
}
  1. Agrega el getter a tu entidad con @Transient.
  2. En la vista (lista), muestra el campo: th:text="${recurso.total}".
  3. Verifica que funciona correctamente.

¿Qué getter implementaste y por qué no se guarda en BD?

Ejercicio 7 — Setter con transformación

Modifica un setter para que limpie o transforme el dato antes de guardarlo:

// Nombre siempre en mayúsculas
public void setNombre(String nombre) {
    this.nombre = (nombre != null)
        ? nombre.trim().toUpperCase()
        : null;
}

// Teléfono: solo dígitos
public void setTelefono(String telefono) {
    this.telefono = (telefono != null)
        ? telefono.replaceAll("[^0-9]", "")
        : null;
}
  1. Elige un setter para modificar.
  2. Agrega la transformación.
  3. Crea un registro con datos "sucios" (ej: " juan pérez ") y verifica que se guardó limpio.

¿Qué setter modificaste y qué transformación aplicaste?

Ejercicio 10 — Verificar redeploy en Render

  1. Abre Render → ve a tu servicio → pestaña Events.
  2. Verifica que el build arrancó automáticamente.
  3. Espera 3-8 minutos.
  4. Cuando esté ● Live, abre la URL pública.
  5. Prueba el login en la URL pública.
  6. Prueba desde el celular.
¡Lo lograste! Si el login funciona en la URL pública, tu app está protegida y en producción.

🎁 Bonus — Mostrar/ocultar según rol con sec:authorize

Si terminaste todo lo anterior, agrega contenido condicional por rol:

  1. Agregar thymeleaf-extras-springsecurity6 al pom.xml.
  2. En tu vista (ej: navbar), agregar: 
    <span sec:authorize="isAuthenticated()">
  Bienvenido, <span sec:authentication="name"></span>
</span>
<a sec:authorize="hasRole('ADMIN')" href="/admin/panel">
  Panel Admin
</a>
  3. Commit + push → verificar en Render.
¿Qué aprendiste? Thymeleaf puede controlar qué ve cada usuario basándose en su rol — sin JavaScript, sin duplicar vistas.
