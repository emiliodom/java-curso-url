Login paso a paso

Implementar un formulario de inicio de sesion con Spring Security. Sin codigo complicado, paso a paso.

Paso 1 — Configuracion de seguridad

Crear una clase que defina quien puede entrar y a donde.

package com.tugrupo.tuapp.configuracion;

@Configuration
@EnableWebSecurity
public class SeguridadConfig {

  @Bean
  public SecurityFilterChain filtro(HttpSecurity http)
      throws Exception {
    http
      .authorizeHttpRequests(auth -> auth
        .requestMatchers("/", "/css/**").permitAll()
        .requestMatchers("/admin/**").hasRole("ADMIN")
        .anyRequest().authenticated()
      )
      .formLogin(form -> form
        .loginPage("/login")
        .defaultSuccessUrl("/recursos", true)
        .permitAll()
      )
      .logout(logout -> logout
        .logoutSuccessUrl("/login?logout")
        .permitAll()
      );
    return http.build();
  }
}

Analogia: es como un guardia de seguridad que revisa credenciales antes de dejar pasar.

Paso 2 — Usuarios en memoria

Para empezar, definimos usuarios directamente en el codigo (sin BD de usuarios aun).

@Bean
public UserDetailsService usuarios() {
  UserDetails admin = User.builder()
    .username("admin")
    .password(cifrador().encode("admin123"))
    .roles("ADMIN")
    .build();

  UserDetails docente = User.builder()
    .username("docente")
    .password(cifrador().encode("docente123"))
    .roles("USER")
    .build();

  return new InMemoryUserDetailsManager(admin, docente);
}

@Bean
public PasswordEncoder cifrador() {
  return new BCryptPasswordEncoder();
}

Nota importante: las contrasenas SIEMPRE se cifran. Nunca se guardan en texto plano.

Roles y permisos

Cada usuario tiene un rol que define que puede ver y que puede hacer.

ADMIN

Administrador

  • Ve toda la informacion
  • Puede crear, editar y borrar
  • Ve los graficos y estadisticas
  • Gestiona usuarios
USER

Docente

  • Ve la informacion general
  • Puede crear registros
  • No puede borrar
  • Ve graficos basicos
ANONIMO

Sin login

  • Solo puede ver pagina de inicio
  • Redirige al login si intenta entrar
  • No ve datos ni graficos
  • No puede crear nada
Analogia para la clase: piensa en un colegio. El ADMIN es el director (acceso total). El USER es un maestro (acceso a su salon). El ANONIMO es un visitante (solo recepcion).

Como proteger rutas por rol

http.authorizeHttpRequests(auth -> auth
  .requestMatchers("/", "/css/**", "/login").permitAll()
  .requestMatchers("/admin/**").hasRole("ADMIN")
  .anyRequest().authenticated()
);

El orden importa: las reglas mas especificas van primero.

Renderizado condicional

Mostrar u ocultar elementos HTML segun el rol del usuario. La vista cambia segun quien este conectado.

Paso 1 — Agregar namespace de seguridad

<html xmlns:th="http://www.thymeleaf.org"
      xmlns:sec="http://www.thymeleaf.org/extras/spring-security">

Sin esta linea, las etiquetas sec: no funcionan.

Paso 2 — Condicionales con sec:authorize

<div sec:authorize="hasRole('ADMIN')">
  <a href="/admin/panel">Panel de administracion</a>
</div>

<div sec:authorize="isAuthenticated()">
  Bienvenido, <span sec:authentication="name"></span>
</div>

<div sec:authorize="!isAuthenticated()">
  <a href="/login">Iniciar sesion</a>
</div>

Condicional con th:if (datos)

<div th:if="${not #lists.isEmpty(recursos)}">
  <table>...</table>
</div>

<div th:if="${#lists.isEmpty(recursos)}">
  <p>No hay recursos registrados todavia.</p>
</div>

Usa th:if para datos y sec:authorize para roles.

Ejemplo completo: boton "Borrar" solo para ADMIN

<tr th:each="r : ${recursos}">
  <td th:text="${r.titulo}"></td>
  <td th:text="${r.tipo}"></td>
  <td sec:authorize="hasRole('ADMIN')">
    <a th:href="@{/recursos/borrar/{id}(id=${r.id})}"
       class="btn btn-danger btn-sm">Borrar</a>
  </td>
</tr>

Consultas a la base de datos

Spring Data JPA genera consultas automaticamente con nombres de metodo. No necesitas escribir SQL.

Repositorio con consultas personalizadas

public interface RecursoDidacticoRepositorio
    extends JpaRepository<RecursoDidactico, Long> {

  List<RecursoDidactico> findByTipo(String tipo);

  List<RecursoDidactico> findByDisponibleTrue();

  List<RecursoDidactico> findByTituloContainingIgnoreCase(
      String palabra);

  long countByTipo(String tipo);
}

Magia: Spring lee el nombre del metodo y genera la consulta SQL automaticamente.

Controlador con filtro

@GetMapping
public String listar(
    @RequestParam(required = false) String tipo,
    @RequestParam(required = false) String buscar,
    Model model) {

  List<RecursoDidactico> recursos;

  if (tipo != null && !tipo.isEmpty()) {
    recursos = repo.findByTipo(tipo);
  } else if (buscar != null && !buscar.isEmpty()) {
    recursos = repo.findByTituloContainingIgnoreCase(buscar);
  } else {
    recursos = repo.findAll();
  }

  model.addAttribute("recursos", recursos);
  return "recursos/lista";
}

Graficos con Chart.js

Visualiza los datos de la BD en barras y donas. El controlador cuenta y la vista dibuja.

Controlador: enviar conteo a la vista

@GetMapping("/estadisticas")
public String estadisticas(Model model) {
  model.addAttribute("videos", repo.countByTipo("Video"));
  model.addAttribute("libros", repo.countByTipo("Libro"));
  model.addAttribute("articulos", repo.countByTipo("Articulo"));
  model.addAttribute("total", repo.count());
  return "recursos/estadisticas";
}

Vista: dibujar el grafico

Flujo de login

sequenceDiagram
  participant U as Usuario
  participant L as /login
  participant S as Spring Security
  participant C as Controlador
  U->>L: Escribe credenciales
  L->>S: POST /login
  S->>S: Verifica usuario y contrasena
  alt Credenciales correctas
    S-->>C: Redirige a /recursos
    C-->>U: Muestra lista
  else Credenciales incorrectas
    S-->>L: Muestra error
  end

Roles y acceso

flowchart TB
  REQ[Peticion del usuario] --> SEC{Spring Security}
  SEC -->|Sin login| LOGIN[/login]
  SEC -->|ADMIN| ADMIN[Todo habilitado]
  SEC -->|USER| USER[Solo lectura y crear]
  ADMIN --> CRUD[CRUD completo]
  ADMIN --> STATS[Estadisticas]
  USER --> READ[Listar y crear]

Consultas JPA

flowchart LR
  URL[URL con parametros] --> CTRL[Controlador]
  CTRL --> REPO[Repositorio]
  REPO -->|findAll| BD[(H2)]
  REPO -->|findByTipo| BD
  REPO -->|findByTitulo...| BD
  BD --> REPO --> CTRL --> VIEW[Vista Thymeleaf]

Renderizado condicional

flowchart TB
  VIEW[Vista HTML] --> CHK{Rol del usuario?}
  CHK -->|ADMIN| ALL[Muestra todo: crear + editar + borrar + estadisticas]
  CHK -->|USER| SOME[Muestra: crear + listar]
  CHK -->|Anonimo| NONE[Redirige a login]
